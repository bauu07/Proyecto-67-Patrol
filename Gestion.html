MÓDULO 01 // MARCO TEÓRICO Y NORMATIVO

EVOLUCIÓN NORMATIVA: ISO 9126 VS. ISO 25000 (SQUARE)

LEGADO CLÁSICO

ISO/IEC 9126 (1991-2001)

Estableció el primer modelo formal de calidad del software estructurado en 6 características troncales aplicadas tanto a la evaluación interna como externa del producto.

  • Funcionalidad & Confiabilidad
  • Usabilidad & Eficiencia
  • Mantenibilidad & Portabilidad
ESTÁNDAR MODULAR

ISO/IEC 25000 SQuaRE

Reemplazo moderno que unifica criterios mediante un sistema de divisiones (2500n a 2504n), integrando explícitamente la Seguridad y la Compatibilidad.

  • Gestión de Calidad (2500n)
  • Modelo de Calidad (2501n)
  • Medición y Requisitos (2502n-3n)
GOBIERNO QA

QA vs. QC vs. Testing

Delimitación estricta de dominios para optimizar la gobernanza del ciclo de vida del software (SDLC) y evitar la superposición de roles operativos.

  • QA: Proceso preventivo sistémico.
  • QC: Verificación de calidad del entregable.
  • Testing: Ejecución y detección de fallos.

Análisis Detallado de Divisiones SQuaRE & ISO 9126

Desglose del Modelo ISO 9126

Este modelo clásico evalúa el software desde dos perspectivas complementarias: calidad interna (código estático, arquitectura) y calidad externa (comportamiento en ejecución), culminando en la calidad en uso percibida por el operador final.

1. Funcionalidad: Capacidad de proveer funciones que satisfagan necesidades explícitas e implícitas bajo condiciones específicas.
2. Confiabilidad: Mantenimiento de un nivel de rendimiento especificado cuando se usa bajo condiciones determinadas.
3. Usabilidad: Esfuerzo requerido para el uso, y valoración individual por parte de un conjunto establecido de usuarios.
4. Eficiencia: Relación entre el nivel de rendimiento del software y la cantidad de recursos utilizados.
5. Mantenibilidad: Esfuerzo requerido para efectuar modificaciones, correcciones o adaptaciones evolutivas.
6. Portabilidad: Aptitud de un sistema para ser transferido de un entorno operativo o hardware a otro.

Arquitectura SQuaRE (ISO/IEC 25000)

La familia de normas SQuaRE orienta la creación y evaluación de productos de software mediante una arquitectura modular estricta dividida en cinco bloques normativos fundamentales.

2500n
División de Gestión

Modelos de calidad comunes, terminología y guía de gestión central.

2501n
División de Modelo

Define características de calidad del producto y calidad en uso.

2502n
División de Medición

Métricas de calidad interna, externa y en uso con fórmulas cuantitativas.

2503n
División de Requisitos

Especificación formal de requerimientos de calidad exigidos al software.

2504n
División de Evaluación

Metodologías y soporte analítico para evaluar productos de software.

MÓDULO 02 // INGENIERÍA CUANTITATIVA

MÉTRICAS DE CÓDIGO Y EFICIENCIA DE DEFECTOS (DRE)

McCabe (1976)

Complejidad Ciclomática $V(G)$

Mide la complejidad estructural cuantitativa del código fuente contando el número de caminos linealmente independientes a través del grafo de flujo de control.

$V(G) = E - N + 2P$ Donde $E$ = Aristas, $N$ = Nodos, $P$ = Componentes conexos (o bien: $V(G) = \text{Predicados} + 1$).
  • 1 - 10: Código estructurado, bajo riesgo.
  • 11 - 20: Complejidad moderada, riesgo medio.
  • > 50: Código altamente inestable y propenso a fallos.
EFICACIA QA

Eficiencia de Detección de Defectos (DRE)

Evalúa la capacidad del equipo de desarrollo y QA para capturar errores antes de que el software sea liberado al entorno de producción de los usuarios finales.

$\text{DRE} = \frac{B}{B + C} \times 100\%$ Donde $B$ = Errores encontrados en pruebas antes de entrega, $C$ = Errores reportados por producción.
B (Encontrados pre-prod): 85 C (Post-prod): 15
Resultado DRE Estimado: 85.0%
MÓDULO 03 // ARQUITECTURA DE VALIDACIÓN

PIRÁMIDE Y NIVELES DE PRUEBAS DEL SOFTWARE

Nivel de Validación Alcance y Componentes Herramientas Estándar Objetivo Técnico Principal
NIVEL 01 Pruebas Unitarias Funciones, métodos, clases y algoritmos individuales aislados. JUnit, Jest, PyTest, NUnit Verificar la corrección lógica elemental de fragmentos mínimos de código.
NIVEL 02 Pruebas de Integración Comunicación entre módulos, llamadas REST APIs y bases de datos. Postman, REST Assured, Testcontainers Garantizar la sincronización y transferencia correcta de datos entre subsistemas.
NIVEL 03 Pruebas de Sistema (E2E) Flujos de usuario completos simulados en interfaces gráficas/navegador. Cypress, Playwright, Selenium Validar el comportamiento integral del software emulando interacciones reales.
NIVEL 04 Pruebas de Aceptación (UAT) Validación de criterios de negocio funcionales junto al cliente o PO. Cucumber, SpecFlow, Criterios BDD Certificar formalmente que el sistema satisface las metas operativas y contractuales.
